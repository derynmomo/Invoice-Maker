# Ledger — Mobile app build & store submission

Ledger is packaged for iOS and Android with **Capacitor**, wrapping the existing
Next.js web app in a native shell. Nothing in the web app was rewritten — the
same React code runs in the native WebView, with two native additions:

- **Speech recognition** goes through `@capacitor-community/speech-recognition`
  (`lib/speech.ts`), so voice works on iPhone and Android inside the app (the
  browser Web Speech API is still used on the plain web).
- **PDF + sharing** work without a server: `lib/mobile.ts` generates the PDF
  client-side with `pdf-lib` and hands it to the OS share sheet (AirDrop,
  Mail, Messages, WhatsApp…) via `@capacitor/share`. The hosted web version
  still uses the server only for PDF generation.

## Prerequisites

| Tool | Needed for | Version |
|---|---|---|
| Node.js | web build | 18+ |
| Xcode + CocoaPods | iOS build | Xcode 16+, CocoaPods 1.14+ |
| Android Studio / JDK 17 | Android build | JDK 17, Android SDK 35 |

## Build the web bundle

```bash
npm install             # also runs patch-package (see below)
npm run build:mobile   # EXPORT_BUILD=true next build -> out/
npx cap sync           # copies out/ + native plugins into ios/ and android/
```

> **iOS speech plugin** — `@capacitor-community/speech-recognition` only ships a
> CocoaPods podspec, but Capacitor 8 links iOS plugins via Swift Package Manager.
> A patch in `patches/` adds a `Package.swift` to the plugin; it is applied
> automatically by `patch-package` on `npm install`. `cap sync` then includes
> the plugin in `ios/App/CapApp-SPM/Package.swift`.

## Run on a device / simulator

### iOS
```bash
npm run ios            # opens the project in Xcode
```
Select your team under **Signing & Capabilities**, pick a simulator or your
iPhone (Plugged in, trusted), then **Run**.

### Android
```bash
npm run android        # opens the project in Android Studio
```
Connect a device with USB debugging enabled, or start an emulator, then **Run**.

### Quick test without building (web/PWA)
```bash
npx serve -s out -l 4173          # serve the static export
cloudflared tunnel --url http://localhost:4173   # public HTTPS URL
```
On Android open the URL in Chrome (voice works; "Add to Home screen" installs
it as a PWA). On iPhone the UI, PDF and share work, but voice requires the
native build — iOS does not allow websites to use speech recognition.

## App identity (change before submitting)

These values must be globally unique and match your developer accounts:

- `capacitor.config.json` → `appId` (`com.ledger.voiceinvoice`)
- iOS bundle id: `ios/App/App.xcodeproj/project.pbxproj` (`PRODUCT_BUNDLE_IDENTIFIER`)
- Android applicationId: `android/app/build.gradle` (`applicationId`)

## Store readiness checklist

- **App icon + splash** — generated by `scripts/generate-assets.js` into
  `assets/`, then `npx capacitor-assets generate` wrote them to both platforms.
  Re-run `node scripts/generate-assets.js && npx capacitor-assets generate`
  after any design change.
- **Privacy policy** — App Store requires a public URL. A starter policy ships
  at `public/privacy.html`; host it on a stable domain and paste the link in App
  Store Connect (and link it in the Play Store listing). It must disclose that
  the app uses the microphone and sends transcribed text to Apple/Google speech
  services for recognition.
- **iOS permissions** — `NSMicrophoneUsageDescription` and
  `NSSpeechRecognitionUsageDescription` are already in `ios/App/App/Info.plist`.
- **Android permissions** — `RECORD_AUDIO` is already in
  `android/app/src/main/AndroidManifest.xml`.
- **Versioning** — iOS `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` and
  Android `versionName` / `versionCode` are set to 1.0 / 1. Bump on each release.
- **Sharing** — the app never calls any messaging API; it opens the native
  share sheet with the PDF, so no server or third-party service is required
  for the phone builds.
- **App Store Connect** — create the app, upload the archive from Xcode
  (Product → Archive), fill metadata (screenshots, description, privacy URL),
  and submit for review. Same flow via Play Console for Android (needs a
  signed release APK/AAB).
